# 팀명 · 카메라 진단 (S15P31A206-262)

기존 `/dev-dashboard`에 API 260의 팀명과 카메라 지표를 표시한다. 기존 개발자 메뉴와 권한 검사 경로를 유지한다.

- 경기 이름은 `teamNames`의 시작 당시 스냅샷이며 이름 없는 과거 경기는 번호와 `이름 미수집`으로 표시한다. 경기 전체 시간과 팀별 완주 기록을 구분한다.
- 카메라 요약은 종료 후 도착한다. 동작별 성공률, 추적 소실 시간 초과, 버전별 FPS/추론 시간, 자리별 인식·젓기 시간 비율을 보여 준다.
- Eagle/team 자동 대기 요청은 기존·카메라 성공률에서 제외하고 별도 제외 횟수를 보여 준다. 취소는 성공률 분모에 포함하지 않는다.
- 경기별 중앙값/p90은 상세에서만 표시한다. 전체 분위수, shadow, near는 후속 데이터 계약 범위이며 수치로 채우지 않는다.
- CSV 버튼은 같은 조회 조건으로 서버의 9개 CSV + export.json을 받는다. 팀명과 camera.csv/camera_requests.csv가 추가됐다.

## 검증

2026-11-10: `npm ci`, `npm run lint`, `npm run build` 통과. 실제 브라우저에서 목록/필터/한글 팀명/미수집 이름/팀별 완주·DNF/카메라 상세/진행 중 요약 수집 대기/빈 조회/CSV 다운로드를 확인했다. 콘솔 오류 없음.

운영에서 읽은 1.1.1 요약 10경기를 새 로컬 계정·경기 ID에 복제해 `review-copy-1.1.1`로 명확히 구분했다. 일부 복제본에 UI 테스트용 팀명을 추가했다. 다운로드 CSV는 경기 10행, 카메라 자리 40행, 카메라 요청 88행이며 API·DB 원본과 일치했다. 가중 평균 FPS 14.450906 → UI 14.5, 추론 시간 51.529999ms → UI 51.5를 대조했다.

API/Unity 명세와 상세 검증은 GitLab `docs/development/camera-dashboard.md`, `camera-dashboard-verification.md`를 참조한다. 새 Unity 실제 Play 검증은 별도 261 작업이며, HTTP 복제 검증을 새 Unity 플레이로 기록하지 않는다.

261 실제 Unity Play도 이후 통과했다. 브라우저에서 두 경기의 플레이 중 → 종료/중단 전환과 팀명 고정/다음 경기 변경을 확인하고 CSV를 다운로드했다. 두 경기의 Unity 원본·DB·CSV가 일치했고, 팀별 완주 69,595ms / 75,750ms와 중단 경기의 미완주(null)를 확인했다. 총 젓기 419회, 동작 성공 29 / 시간 초과 1이다. 입력은 자동 검증이며 새로운 사람/카메라 인식 품질 테스트를 의미하지 않는다.

## 반영

API 260을 먼저 배포하고 이 웹을 반영한다. 새 팀명 수집은 Unity 261 포함 빌드가 필요하다. 기존 운영 권한과 DB 구조는 변경하지 않는다. 이 작업은 feature → develop PR 생성까지만 수행하며 승인/병합 및 운영 배포는 사용자가 진행한다.
